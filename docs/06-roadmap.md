## 1. หลักการแบ่งขอบเขต

1. **MVP ต้องตอบความต้องการเดิมของลูกค้าครบทุกข้อ** (ตารางในหัวข้อ 2.1) และใช้งานจริงได้ตั้งแต่วันแรก ไม่ใช่ demo
2. **ฟีเจอร์ที่ "ดีถ้ามี" แต่ไม่กระทบงานประจำวันเลื่อนไป Phase 2** เช่น อีเมล ลากวาง KPI ผลลัพธ์ที่ช่วงแรกยังไม่มีข้อมูลพอ
3. **ข้อมูลเชิงพาณิชย์และการเชื่อมระบบภายนอกอยู่ Phase 3** เพราะต้องตกลงรูปแบบข้อมูลกับหลายฝ่ายก่อน
4. **ต่อยอด prototype ที่มีอยู่** ไม่เปลี่ยนเครื่องมือ (npm workspaces, react-router 7) ระหว่างทำ MVP
5. ทุกจุดที่ทีมออกแบบสันนิษฐานไว้ มีค่าเริ่มต้นที่ทำงานต่อได้ทันที และมีคำถามในหัวข้อ 5 ที่ต้องได้คำตอบตามกำหนด

### 2.4 Phase 3

- เงื่อนไขการค้าแบบมีโครงสร้าง (listing fee, GP, DC fee, rebate, ค่าเช่าพื้นที่, ค่า PC/BA) และ KPI trade spend เทียบงบ
- KPI เชิงพาณิชย์: นำเข้า sell-in/sell-out, rate of sale, OOS, distribution, delist risk, ROI ของ Exclusive shelf และ KPI ออนไลน์ (GMV, ROAS)
- ติดตามรายสาขาและ format: store list ต่อข้อเสนอ รูปยืนยันหน้าชั้นทุกสาขา shelf execution compliance
- สัญญาเช่าพื้นที่ Exclusive: anchor date (วันสิ้นสุดสัญญา) เตือนก่อนหมดสัญญา audit พื้นที่รายเดือน
- override รายห้างและประเภทสินค้า (เช่น 7-Eleven ต้องเริ่มเร็วขึ้น) และ template block / add-on
- เชื่อม ERP สำหรับ product master และเชื่อม B2B portal ของห้าง / API ของ marketplace
- ขั้นตอนอนุมัติข้อเสนอก่อนเริ่ม และหน้าแก้ matrix สิทธิ์ (ตาราง Role/RolePermission)
- UI ภาษาอังกฤษ dark mode PWA/offline สำหรับทีมภาคสนาม

## 7. Go-live checklist

**ข้อมูล**
- [ ] นำเข้าสินค้าที่ใช้อยู่ทั้งหมด (ตรวจ SKU และบาร์โค้ดซ้ำแล้ว)
- [ ] สร้างบัญชีผู้ใช้จริงและกำหนดบทบาท มี ADMIN ที่ Active อย่างน้อย 2 คน
- [ ] ตรวจรายชื่อห้าง/แพลตฟอร์ม รูปแบบชั้นวาง โลโก้ และแม่แบบงานกับทีม Trade
- [ ] ลบ `SEED_ADMIN_PASSWORD` ออกจาก `.env` หลัง ADMIN คนแรกเปลี่ยนรหัสแล้ว

**ระบบ**
- [ ] HTTPS ใช้งานได้ HSTS และ security header ครบ
- [ ] `ENABLE_DEMO_LOGIN=false` และ build เว็บใช้ `VITE_API_MODE=http`
- [ ] backup คืนแรกสำเร็จ และซ้อมกู้คืนลง staging ผ่าน (จดเวลาเทียบ RTO)
- [ ] cron 08:00 ทำงานบน production (ตรวจจากการแจ้งเตือนของวันแรก)
- [ ] `/api/readyz` ถูกตรวจจากภายนอก และมีคนรับแจ้งเมื่อระบบล่ม
- [ ] runbook deploy / rollback / backup-restore / break-glass อยู่ใน repo และทีม IT ได้อ่านแล้ว

**คุณภาพ**
- [ ] CI เขียวทั้งหมด รวม RBAC matrix, IDOR, CSRF, upload test
- [ ] Playwright เส้นทางหลักผ่านที่ 1440/1280/1024/768/375 px และ axe ไม่มี violation ระดับ serious
- [ ] task list 500 งานแสดงผลภายใน 1 วินาที dashboard ภายใน 2 วินาที
- [ ] UAT sign-off ไม่มี bug critical/major ค้าง

**ผู้ใช้**
- [ ] อบรม key user และส่งคู่มือสั้น (สร้างข้อเสนอ, จัดการงาน, ปิดข้อเสนอ)
- [ ] ช่องทางแจ้งปัญหาช่วง hypercare 2 สัปดาห์
- [ ] นัดทบทวนลำดับ Phase 2 หลังใช้งาน 1 เดือน
